# AGENTS.md — hits-rs

## Workspace structure

Five Cargo crates in one workspace:

| Crate | Kind | Role |
|---|---|---|
| `hits-rs` (root) | binary | 3-line entry point; calls `hits_api::start()` |
| `api/` | library | All business logic; handlers, services, DTOs, utils, workers, test support |
| `entity/` | library | SeaORM entities — **code-generated**, do not edit by hand |
| `migration/` | lib + binary | Migration definitions + sea-orm-migration CLI |
| `macros/` | proc-macro | `#[has_role]`, `#[has_any_role]`, `#[has_all_roles]`, `#[derive(IntoDataResponse)]` |

## Commands

```bash
# Build / run
cargo build
cargo run                  # requires .env in repo root

# Test (requires live Postgres + .env)
cargo test                 # all workspace tests
cargo test -p hits-api --test auth           # single integration test file
cargo test -p hits-api --test auth login_sets_cookies  # single test function

# Lint / format
cargo clippy -- -D warnings
cargo fmt --check          # check only; cargo fmt to apply

# Migrations (apply / rollback / status)
cargo run -p migration -- up
cargo run -p migration -- down
cargo run -p migration -- fresh              # DROP all + reapply (DESTRUCTIVE)
cargo run -p migration -- status

# Re-generate entity crate after schema changes
sea-orm-cli generate entity \
  --output-dir ./entity/src \
  --lib \
  --entity-format dense \
  --with-serde both

# Create a new migration file
sea-orm-cli migrate generate <name>
```

## Required services

Both must be running before `cargo run` or `cargo test`:

```bash
docker run -d --name hits \
  -e POSTGRES_DB=hits -e POSTGRES_USER=lexunok -e POSTGRES_PASSWORD=password \
  -p 5434:5432 postgres:16

docker run -d --name redis -p 6379:6379 redis:latest
```

Or: `docker compose up` (maps app→8080, db→5432, redis→6379).

**Postgres defaults to port 5434 locally** (non-standard; avoids conflicts with a system install). `docker-compose.yml` uses the standard 5432 inside the Docker network.

## Environment variables

Loaded from `.env` via `dotenvy`. Missing required vars cause a **panic at startup** (via `LazyLock`).

Required: `DATABASE_URL`, `REDIS_URL`, `JWT_SECRET`, `CLIENT_URL`, `ADMIN_USERNAME`, `ADMIN_PASSWORD`, `SMTP_HOST`, `SMTP_FROM`, `AVATAR_PATH`

Optional: `PORT` (default 3000), `SMTP_USER`, `SMTP_PASSWORD`, `DISABLE_SMTP` (set `true` to skip email), `DISABLE_REDIS_STREAM` (set `true` to skip Redis Streams writes)

## Architecture notes

- **Startup auto-migrates**: `Migrator::up()` runs on every `cargo run` and every test run — no manual migration step needed.
- **Auth is cookie-based**: JWT tokens live in `HttpOnly` cookies (`access_token`, `refresh_token`). The `Claims` extractor reads the cookie, not an `Authorization` header.
- **Role macros**: handlers use proc-macro attributes — `#[has_role(Admin)]`, `#[has_any_role(Admin, Expert)]`, `#[has_all_roles(...)]` — which inject a role check returning `AppError::Forbidden`.
- **Soft deletes**: users use `is_deleted: bool`; skills use `deleted_at: Option<DateTime>`. List queries filter these out.
- **Pagination**: `?page=0&page_size=10` query params on list endpoints.
- **Redis Streams**: `invitation_worker` (background Tokio task) reads `invitations_stream` and sends invitation emails via Tera templates.
- **Cookies not Secure in debug builds**: `cfg!(debug_assertions)` controls the `Secure` cookie flag, so HTTP works locally.

## Testing

All tests in `api/tests/` are **full HTTP integration tests** against a real Postgres — no mocking.

- `tests/common/mod.rs`: shared helpers — `setup()`, `login_and_get_cookies()`, `unique_email()`, `json_body()`
- `api/src/test_support.rs`: `prepare_clean_db()` truncates all 25 domain tables with `RESTART IDENTITY CASCADE`; `seed_*` functions for every domain entity
- `setup()` sets `DISABLE_SMTP=true` and `DISABLE_REDIS_STREAM=true` automatically
- **Every test must use `#[serial]`** (from `serial_test` crate) — tests share one DB and truncate on each `setup()` call; missing `#[serial]` causes data races
- `unique_email("prefix")` generates collision-resistant emails using nanosecond timestamps
- Tests do **not** use a separate test database — they reuse `DATABASE_URL` from `.env`

## Entity crate

`entity/src/lib.rs` header: `// @generated by sea-orm-codegen`. After any schema change:
1. Write and apply the migration (`sea-orm-cli migrate generate` + `cargo run -p migration -- up`)
2. Re-run the `sea-orm-cli generate entity` command above
3. Review the diff — some entities may be manually maintained alongside generated ones
